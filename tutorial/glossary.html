Dart & Flutter

TermMeaning
WidgetA declarative description of a piece of UI in Flutter. Widgets form a tree; Flutter rebuilds the parts of the tree whose inputs changed. Roughly: a React component, but for layout too — there is no separate HTML/CSS.
StatefulWidgetA widget that owns mutable state and can call setState() to trigger a rebuild of itself.
ChangeNotifierA stdlib class with a notifyListeners() method. Widgets that listen to it rebuild when it fires. This project's whole "publish state changed" mechanism, with no external state-management package.
InheritedWidgetA widget that makes a value available to every widget below it in the tree without passing it through every constructor — Flutter's built-in dependency injection.
StreamA push-based sequence of values delivered over time, one at a time, as they happen (dart:async). Compare to a message queue with one consumer.
FutureDart's name for a promise — a value that will be available later, awaited with await.
const constructorA constructor whose result is compile-time-constant and immutable — Dart/Flutter can reuse the same instance everywhere it's constructed identically, which is both a correctness signal (this object never changes) and a small performance win.
enumA fixed, named set of values (e.g. Suit.spades). Dart enums can carry methods via extension.
extensionDart syntax for adding methods/getters to a type you don't own (or don't want to put instance logic inside), e.g. extension SuitInfo on Suit.
sealed classA class whose subtypes are all known and declared in the same file. A switch over a sealed type must be exhaustive — the compiler rejects a missing case, catching bugs that a dynamic language would only find at runtime.
switch expressionA switch used as an expression that returns a value, e.g. String get code => switch (this) { ... } — no break, no fallthrough.
null safetyDart's type system distinguishes String (never null) from String? (may be null) at compile time, so a null-dereference bug is usually caught before the code ever runs.
hot reloadFlutter injects changed code into a running app in under a second, preserving state — the fast edit/see loop that replaces "rebuild and redeploy."

Go & backend

TermMeaning
goroutineA function that runs concurrently, scheduled by the Go runtime rather than the OS. Far cheaper than an OS thread — a Go program can run thousands of them, which is what makes "one goroutine per game table" affordable.
channelA typed pipe goroutines use to send values to each other safely, without a lock. Go's proverb: "don't communicate by sharing memory; share memory by communicating."
actor modelA concurrency pattern where one unit of state is owned exclusively by one worker, and everyone else talks to it only by sending messages to an inbox, never by touching its memory directly. This project's internal/room package is one actor per game table.
mutexA lock that lets only one goroutine touch a piece of shared state at a time. The actor model above is a way of avoiding needing one on the hot path.
panic / recoverGo's exception mechanism. A panic unwinds the stack; a deferred recover() can catch it and keep the process alive instead of crashing entirely.
token bucketA rate-limiting algorithm: a bucket refills with "tokens" at a fixed rate and each unit of work spends one; if the bucket's empty, the work is refused. Bursts up to the bucket size are allowed; sustained rate is capped.
graceful shutdown / drainStopping a server by first refusing new work, then waiting for in-flight work to finish (up to a timeout), instead of killing everything mid-request.
connection poolA small, reused set of already-open database connections, handed out to callers and returned rather than opened fresh per request — opening a new DB connection is expensive.
migrationA versioned, ordered SQL script that changes a database's schema (e.g. 0001_init.sql), applied in sequence so every environment's schema history is reproducible.

Networking & general

TermMeaning
WebSocketA single long-lived TCP connection that lets client and server send messages to each other at any time, in either direction, without the request/response back-and-forth of plain HTTP.
RESTAn HTTP API style where each request is a self-contained call to a resource URL (GET /v1/games) — used here for things that aren't a continuous session (auth, profile, match history), while the WebSocket carries the live game.
JWTJSON Web Token — a signed, tamper-evident blob of claims (e.g. "this is guest player p_9f3c") a client can hold and present, without the server needing to look it up in a session store.
idempotentAn operation that has the same effect no matter how many times it's repeated — important for anything a flaky network might cause a client to retry.
redaction (server-authoritative view)The server holds the full game state but sends each player only what they're allowed to see (their own cards in full, everyone else's as a count) — the client never receives data it isn't entitled to.
horizontal scalingHandling more load by running more copies of a stateless(ish) server behind a load balancer, instead of making one machine bigger.
UDP broadcastSending one network packet to every device on the local network segment at once, with no guarantee of delivery — used here so a phone can announce "I'm hosting a table" without knowing anyone's address in advance.
CI/CDContinuous Integration/Continuous Deployment — automatically running tests (and often deploying) on every code change, usually via a hosted pipeline like GitHub Actions.
